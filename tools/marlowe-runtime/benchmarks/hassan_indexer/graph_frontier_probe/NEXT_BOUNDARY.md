# Next targeted hypothesis: a distributed graph boundary

The v4 traces expose a specific boundary cost: the first pair has about3.4µs Q/K start skew, whereas inner grouped pairs overlap almost completely. The inference is graph-entry synchronization overhead. This does not establish a command-processor bug, and v4's measured performance/regression gates come first.

Current v4 publishes an all-lane join on the launch queue at the end of every graph. The next graph's main lane follows that join by queue order; each side lane also executes an AND wait on its completion before the first kernel. This creates a final-join-then-entry-wait chain across each graph boundary. Inner pairs consume their opposite lane's preceding segment token directly. A first-principles candidate is to give both sides the same kind of direct predecessor edge across graph launches.

For a compatible next graph, retain the previous graph command and its full set of physical-queue tails. Each first-use physical queue waits on every previous tail from a different physical queue; same-queue ordering covers its own tail. Thus every new graph root remains ordered after every previous graph leaf. This preserves the full launch-stream happens-before relation, including unknown aliasing between graphs. Do not remove dependencies merely because the observed Hassan inputs happen to be independent. Queue assignment/launch-stream changes must use physical queue identity, not logical lane number.

Defer the all-lane join to an ordinary observer/command, a watermark, resource-cap pressure, graph destruction or stream destruction. A preallocated bridge must consume the complete current tail set and perform the required SYSTEM release before exposing public completion. Ordinary predecessors still need explicit import/system acquire for host/copy visibility. Failed partial publication must expose only the sealed touched-prefix tails and preserve ownership. No CPU reads/polling of private GPU tokens.

This changes the boundary representation, not the application graph or kernels. It needs a source proof for public events before later work, callbacks, stream query, copies, launch-stream switching, graph update, failure cleanup and queue destruction. Exact compiled-kernel and argument ownership remain per-generation. Predecessor tail storage stays leased until every successor reader retires, and error handling must not recycle storage. A bounded pending-command resource policy is required so deferred retirement cannot grow without bound.

A falsifying experiment would compare identical bytes with current versus distributed boundaries on the unchanged g1/g50 protocol, timestamps off, plus a separate timestamp proof. Prediction: g1 start skew and total time improve; g50 gains mainly at its first pair and should change little per pair. If performance improves only by relaxing ordering or serializing lanes, reject it. This is a design candidate only; it is not implemented or a result.
