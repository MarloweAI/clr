# Graph-frontier diagnostic implementation

This is a default-off experiment based on the preserved v3 graph-local runtime (baseline commit7d32325, HIP69f3df4). The parent has other diagnostic changes; this is not the clean production PR requested for Goal2. Goal1 remains unchanged Hassan Q/K work with real parallel execution and cheap synchronization, followed by other microbenchmark holdouts.

The new GPU_GRAPH_DIAGNOSTIC_FRONTIER control admits flat, enabled captured-kernel graphs on a single gfx950 agent, with direct dispatch and profiling disabled. Unlike the previous local-token experiment, two independent root branches are eligible: the graph's final all-lane join is their consumer. Kernels and application graphs are unchanged.

Each launch owns segments+2 private signals: one per segment, entry, final frontier. Creation caches the ROCr value-pointer API result; reuse writes only the signal value and executes SFENCE. No private signal is passed to HwQueueTracker, HwEvent, CPU waits, callbacks or native-wait admission. Packet copies and every possible prefix-final join are allocated before publication. First kernels on each physical lane acquire SYSTEM, other original kernel fences are preserved, and the final ordered AND sequence acquires AGENT/releases SYSTEM after the last packet on every touched physical lane. More than five terminal dependencies use ordered AND packets with SYSTEM release only on the last. Topological publication ensures a queue cannot fill while waiting on an unpublished producer.

The launch stream gets an ordinary CLR GraphFrontierCommand whose submit is a no-op after the packets are published under the same execution lock. It remains in the ordinary batch without forcing CL_TASK retirement. A following graph retains the prior command and consumes its private frontier on side lanes; the main queue already orders after the prior final join. First/nonchained graphs notify and retain an ordinary predecessor outside all execution locks, then validate the exact retained tail after acquiring execution locks in canonical order. A notification-created marker is accepted as the new tail; concurrent newer submission causes retry.

An ordinary command consumes a preallocated GraphFrontierMarker before its own submission. That marker imports the private frontier through a raw GPU wait, then creates a normal profiling signal and callback to retire the host batch. Its command/timestamp/batch head are ordinary; no private token enters that machinery. The existing watermark uses the preallocated bridge directly. It bounds unsealed batch length, but callback lag can retain additional generations; a hard resource-capacity policy is still required. Notify/query/event/callback/copy/stream-sync/stream-destroy routes therefore use the same pre-submit bridge. GraphExec destruction remains asynchronous and may leave a bounded lease on a live idle stream until its next observer, watermark or destruction, as with CLR deferred batches.

Ownership is split: successful command completion releases its predecessor lease (all reads of the prior token have retired), while its own generation survives until its final command reference. This prevents an unbounded transitive chain across batch watermarks. Callback/cleanup handoff uses atomic pointer exchange. A failed asynchronous completion preserves references and quarantines rather than recycling. The partial-publication diagnostic publishes a prebuilt join of only the touched lanes before reporting the injected API error; ordinary successful retirement can then prove that prefix drained.

Independent Codex xhigh hook review accepted these transitions and the callback split.
