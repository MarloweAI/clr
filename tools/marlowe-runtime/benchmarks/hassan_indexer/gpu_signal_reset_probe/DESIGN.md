# GPU signal reset: total-path feasibility

Job55065 established a 25.81% direct execution gain for GPU-local internal completion storage, but CPU preparation/readback/verification was outside its primary interval. This follow-up uses the exact same HSA2899 private ownership implementation and original Q/K packets. It adds one generic GPU scatter-reset helper and measures the complete replay path from immediately before preparation/publication until both ordinary host-visible exits complete.

Modes: m0 normal pooled host signals reset by CPU; m1 private host signals reset by the GPU; m2 identical private GPU-local signals reset by the same GPU helper. m1/m2 isolate location with matched reset implementation; m0 is the useful normal-path reference. The primary metric is total_us/200 in profiling-off runs. The old 200us deliberate gate hold is removed. No CPU accesses an internal GPU-mode signal from measurement start until both exits and queue retirement. Post-drain numerical/guard/profiling checks are outside timing.

For m1/m2, queue0 starts with its ordinary SYSTEM-acquire entry gate, then a captured reset dispatch with SYSTEM acquire/release scopes. It writes only value=1 and start_ts=end_ts=0 through an immutable device table of existing legitimate signal ABI addresses. It does not touch kind, core_signal, id or guards. Both lanes have an ordered SYSTEM-acquire AND on that dispatch's ordinary host reset_done completion. Original Q/K kernels, arguments, ordered bits, AGENT fences and 398 inter-pair ANDs are unchanged. Normal packets/lane401; GPU-reset mode403 on lane0 and402 on lane1.

The reset kernel is warmed/captured separately. Its graph, kernargs, device table and module stay live until both private queues are drained and destroyed. Untimed controls poison every value to7 and both timestamps to0xdeadbeef, execute both eager/captured reset, and verify1/0/0 plus guards. The helper's actual packet, resource geometry, arguments, code-object address, table contents and helper ELF hash are retained. Full-run checks prove all400 distinct values decrement back to0 and the original Q/K outputs match changed/restored FP32 references. Profiling-on runs retain reset endpoints and require both first Q/K dispatch starts after reset end.

A short original-kernel g1/two-pair capability run precedes g50/200-pair timing. Four rotated rounds retain eight trials per cell. No allocator/packing change, admission rule or application/kernel modification is mixed into this test. This is still a direct-packet lower-layer prototype; even a positive total_us result requires integration under unchanged HIP/PyTorch graph replay and a matched serial/two-stream comparison. Initial signal allocation and graph/module construction are outside replay timing, as in the prior workload. A graph-owned arena/inflight generation design is the subsequent integration task, not a claim made by this test.
