# First-release / second-acquire fence discriminator

Prior job54716 is a correct negative result: zero rendezvous-positive layers on one AQL queue with kernel scopes SYSTEM/SYSTEM. Even one-block kernels ran sequentially, so geometry/resource exhaustion cannot explain that cell. Original captured Q/K kernels normally use AGENT/AGENT scopes. Do not generalize the pilot to all fence configurations or to firmware causality.

This follow-up uses byte-identical probe sources and no runtime port. An ordered entry barrier with SYSTEM acquire / NONE release publishes host inputs; an ordered exit barrier with NONE acquire / SYSTEM release owns the sole completion. Therefore removing per-kernel fences in this independent-kernel test does not discard host publication or final data lifetime. All kernel completion signals are zero. Every same-queue sequence is prepared and co-published in one reservation/doorbell.

The primary 3x3 causal grid changes the first dispatch release scope (SYSTEM, AGENT, NONE) and the second dispatch acquire scope (SYSTEM, AGENT, NONE) independently; first acquire and second release stay SYSTEM. Their barrier bits stay1/0. Exact AGENT/AGENT and NONE/NONE pairs are additional controls. SYSTEM/SYSTEM, AGENT/AGENT and NONE/NONE 0/0 controls test whether the first kernel's barrier bit itself prevents concurrency even after an explicit ordered entry barrier. SYSTEM and NONE serial1/1 controls must never rendezvous. The two-queue SYSTEM/SYSTEM control uses the same kernels/data and one final completion per queue. Both entry barriers share an initially pending CPU-controlled signal; both queues are published/rung before host releases the gate, removing publication skew. Host waits both completions before reading or freeing. Any second-queue publication exception after the first is live uses fail_inflight/_Exit, never resource unwinding. Q-first/K-first reverses publication, resources and duration order. There are17 fixed configurations,4 reversed rounds,2 orders,2 geometries=272 one-layer trials. This is a causal fence grid, not a timing/tuning sweep; every trial uses the same1.5/2ms bounded capability workload. Both geometries are included in the same short script to avoid another launch cycle. This is not original Hassan timing.

Outcome policy: correctness and positive-control success are distinct. Serial false-positive or malformed packet/output fails the audit. Two-queue failures mark the positive control FAIL and prohibit interpreting same-queue negatives. Same-queue cells report exact successful rendezvous counts. A successful reduced-fence cell would require a separate graph memory-ordering design and original-kernel validation before any runtime use. No fence weakening is applied to user workloads by this experiment.
