# Same-queue parallel-layer capability probe

This is a standalone HSA packet/ordering experiment, not a Hassan timing result or a runtime candidate. It asks whether MI355X executes independent dispatches concurrently on one AQL queue when kernels and their join are co-published. One root launches and monitors one GPU on node2.

A layer has two original probe kernels then an ordered empty Barrier-AND. In the parallel arm kernel barrier bits are 1/0; serial control 1/1. Every kernel retains SYSTEM acquire/release, completion zero. The final join carries the sole completion signal and SYSTEM scopes; intermediate joins have no scopes or dependencies. All layers are prepared before a single reservation; the first header remains INVALID (packet type 1) until all bodies and subsequent headers are written; one release header publication and one doorbell follow. No interqueue signals, native packets, HIP library, or kernel changes between arms.

Two independently launched kernels write their own started flag then poll their peer with a bounded GPU deadline. Both seeing the peer proves simultaneous progress without relying on synchronized XCD clocks. Serial first kernel must time out. Delays are asymmetric and reversed in controls; every block in later layers checks both preceding outputs and release/acquire completion counters for ALL preceding workgroups. Per-block timestamps are retained but cross-XCD overlap alone is not treated as proof. Cases: 1+1 blocks with minimal LDS; 256+24 blocks with 128 threads and 61,440 dynamic LDS bytes, matching Hassan's geometry/resource reservation but NOT its MFMA/memory workload. Test one and eight fully joined layers, forward/reverse kernel publication, fresh epochs, four rounds, and a forced queue-wrap boundary. All inputs and argument storage live until completion.

The bounded 1ms rendezvous and 1.5/2ms delays intentionally make a concurrency opportunity. This is not a short-kernel speed benchmark. Co-residency success is necessary but does not prove useful Q/K overlap at ~4us. If it succeeds, implement the generic runtime plan and test original kernels; if it fails, inspect packet receipts and scheduling before porting runtime complexity.

Failure policy: prevalidate capacity and allocate everything before reservation; no allocation or throw after reservation. A live-queue fault or timeout exits without freeing in-flight GPU memory. A requested batch larger than capacity is rejected before changing the write index, and an exactly full batch of empty barriers is an independent capacity test. Repeated launches cross queue wrap. Metadata, packet receipts, binaries, ISA, raw samples, hashes, and actual mapped HSA identity are retained. Counter/profile helper is unnecessary.
