# Next bounded hypothesis: parallel graph layers on one AQL queue

Status: source/architecture reviewed by the existing Codex xhigh reviewer; NOT implemented or measured. Finish and audit54609 before making this the next experiment. Start from exact K source contents d4d8e82 / HIP0e7d285 baseline, not the polling branch. No full model, no shape/name thresholds, no serialization-as-success.

The original warm Hassan graph already permits useful Q/K overlap. Earlier calibrated wave traces show that overlap is canceled by the interval before the next pair. Completion-packet removal helped; internal publication reduced CPU submission but was GPU-neutral. GPU polling adds dispatch and resource costs. The next question is whether a fully joined graph can express its actual partial order with same-queue dispatch ordering, avoiding cross-queue completion signals entirely.

Hassan's retained g50 DOT contains50 layers of two kernels. Each node after layer0 has BOTH nodes of the immediately preceding layer as direct dependencies. The g1 case is one independent two-root layer. This structure is an inherent global join, so batching such a layer does not add a dependency that the graph lacked. Structural eligibility can recognize it without knowing tensor shapes, kernel names, execution times or application identity.

AQL permits independent dispatches to be outstanding on one queue. A conservative layer sequence is:

1. First original kernel: barrier=1, completion=0.
2. Other independent kernels in that layer: barrier=0, completion=0.
3. Barrier-AND: barrier=1; no dependency handles. Intermediate joins have no completion signal. The final join owns the normal command completion/IRQ and system-scope retirement fence.

The first packet cannot launch until preceding queue work completes; subsequent independent packets can issue after it without waiting for that kernel's completion. The layer's ordered barrier joins every prior dispatch. Keep each original kernel's acquire/release scopes, geometry, code object and kernargs. Entry ordering and imported host/device fences must be preserved for every root, without assuming an arbitrary last kernel represents all sibling completion. First prove this sequence and its memory visibility; do not initially optimize away the explicit intermediate barriers.

This differs from old logical coalescing and GPU_MAX_HW_QUEUES=1, which retained barrier=1 on every kernel and serialized. The existing source already uses hipExtAnyOrderLaunch for a narrow sibling pattern under DEBUG_HIP_FORCE_ASYNC_QUEUE plus DEBUG_HIP_FORCE_GRAPH_QUEUES=1 (hip_graph_internal.hpp CreateCommand; rocvirtual.cpp clears HSA_PACKET_HEADER_BARRIER). Those broad flags do not cover Hassan's two-predecessor later layers and are not a proposed runtime policy.

Publication is critical. The current dispatchGenericAqlPacketBatch publishes chunks of1,2,4... and rings each chunk, potentially letting Q finish before K is visible. Do not reuse that publisher unchanged. A dedicated mixed kernel/barrier publisher must prevalidate every packet and allocate/register the ordinary final completion before reserving the entire bounded packet sequence. Write the complete sequence with its first header invalid, release-publish that first header once, then ring the terminal index once. If capacity requires chunking, publish complete layers atomically; never split an independent layer across doorbells for the decisive experiment. A queue-capacity capability bound is legitimate; a workload shape/duration threshold is not.

Minimal HIP plan: after packet capture, cache eligible graph layers using the existing segment/PacketBatch::NodeRange maps. Initially require each segment to be one enabled captured kernel node with exactly one dispatch packet, one device, no root dependencies, and each later dependency set exactly equal to the prior complete layer. Reject child/cooperative/multi-packet/disabled/ragged/skipping DAGs, mask/priority/device mismatches, profiling/activity, dynamic/forced-async/non-direct modes and unsupported packet headers. Fall back untouched. Updates, parameter changes, enable/disable and launch-device/stream changes must refresh or invalidate the plan; retain graph packet/kernarg ownership through execution.

One launch-stream AccumulateCommand can own the whole execution. Extend its established immediate borrowed-vector/deferred-submit lifetime pattern. Do not create side commands/markers or reuse tail-kernel completion from K: the last barrier=0 kernel may finish before another sibling. NoteNativeKernelPacket must use actual packet indices, synthetic barriers must have the ordinary appropriate history behavior, and TrackQueueProgress must reflect the actual final barrier. Existing native bookkeeping may not describe packets that were not published.

Failure handling: prevalidation/preparation failure before reservation takes the ordinary untouched graph path. No throwing/allocation work or fallible hole may occur after reservation. After publication, the final barrier completion owns the published work; errors must retain that completion and return a sticky launch error, never duplicate an IRQ or replay the graph. A partial multi-layer publication failure must retire the published prefix through ordinary fallback; no omitted sibling can leave a permanently incomplete reserved span.

First gate: an untimed controlled two-kernel layer with device wall-clock intervals, asymmetric durations and an output-consuming join. Require actual overlap on one physical queue, correct producer-to-next-layer ordering, exact header sequence1/0/1, zero kernel signals, nonzero final barrier signal, co-publication/doorbell receipts, and no cross-queue dependency/native-wait packets. Exercise wrap/capacity, immediate graph destruction, updated inputs/parameters, invalidation and prepublication failure before performance. Queue semantics alone do not prove hardware overlap.

Then use ORIGINAL Hassan kernels and unchanged benchmark protocol. Verify50 original two-node layers, identical objects/geometry/kernargs/scopes, actual same-queue overlap with a separate calibrated probe, and the uninstrumented serial/events g1/g50 stock/parent/new-off/new-on comparisons in balanced orders. The atomic same-queue barrier=1-all-kernels variant is an important serialized control: it isolates publication/planning benefits from actual any-order concurrency. A win must beat stock and own serial before broad micro holdouts; no full model.

Main risk: a single queue may submit all256 Q workgroups before the24 K workgroups. MI355X resource capacity permits co-residency, but command-processor arbitration may still prevent useful overlap. That is a measurable failure mode, not a reason to claim theoretical overlap as achieved. If the untimed controlled layer or original calibrated trace cannot demonstrate concurrency, stop and explain the scheduler limitation before tuning.

The unrelated per-stream CU-mask shutdown holdout has exact upstream fixes4e2396f8 and9a25d0be (see SHUTDOWN_BLOCKER.md). Do not graft speculative mask guards into this hypothesis. A future production candidate needs that independent lifetime fix/requalification if custom-mask support is in scope.
