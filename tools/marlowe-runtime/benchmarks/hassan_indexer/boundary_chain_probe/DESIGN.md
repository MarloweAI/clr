This preserves the uninterrupted batch's execution and memory semantics. It does NOT by itself preserve separately observable per-launch host retirement. The contrast combines entry fusion, completion placement and deferred CPU retirement; do not attribute it solely to one component. A positive result is architectural headroom, not a runtime/stock/serial win.

Any actual HIP port must retain a distinct private completion and owner lease for each launch, then materialize the exact boundary when required: sync/query, event record/wait, callbacks/host nodes, ordinary commands, cross-stream/agent/SDMA use, resource destruction/free/update where API ordering requires it, capacity pressure and failure. Concurrent host calls must serialize against extending the chain. Every launch can end in a private token immediately; the runtime must not predict a future launch or require an application change. Ineligible boundaries use ordinary retirement. Private completion must never be imported into CPU-wait/IRQ machinery or recycled before every consumer retires.
